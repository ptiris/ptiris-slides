# Ref 的图示与讲述方式

参考文件：[GPU Programming 样例](../../Ref/gpu-programming-slides/index.html)。重点观察了 Memory Coalescing、Warp Divergence、Double Buffer 三页。

## 先交代一个具体条件，再让图回答问题

Memory Coalescing 先限定每个 thread 访问一个 4B 的 int，再比较连续地址与跨步地址。图里的 transaction 数量因此有明确来由，观众不需要先记一串定义。

本报告先交代实际任务：第一例在 GSM8K 上评测模型，第二例让机器人完成操作任务。背景、过程、结果放在同一页，讲述时从上到下、从左到右即可。

## 保持位置一致，只改变需要比较的内容

Memory Coalescing 的两组图保持 thread 的排列，只改变下面的地址分布和 sector 分组。Warp Divergence 的两个阶段保持 lane 位置，只改变 active / masked 状态。观众可以直接对齐比较。

评测案例因此使用相同的 8 个 GPU 列，分别画先、后两个阶段。计算块从 GPU 0 移到 GPU 1，其余位置保持不变。两行表示执行阶段，不是按实测时长绘制的时间线。

## 让形状承担解释

样例用框的包含关系表达存储层级，用对齐的格子表达 thread 与数据的对应，用时间线表达搬运和计算能否重叠。图形对应对象与关系，而不是给每句文字套一个卡片。

Robot Harness 使用闭环：图像和动作记录进入模型，工具调用驱动动作，新图像再回到下一轮。回路表达执行后获得新观测的依赖关系。节点宽度不表示时间，也不虚构每轮耗时。

## 颜色标记状态，结果采用普通字级

样例中的亮色表示当前活动的 lane、计算或搬运，灰色表示 inactive / masked 等状态，文字标签补足颜色含义。

新图沿用同样的原则：蓝色表示当前计算或动作执行，灰色表示等待，浅黄色标出模型推理环节。时间和完成情况作为右侧结果列，与正文使用相近字级，不单独放大成视觉中心。

## 一页完成一次解释

样例通常在图下给出与图直接相关的判断，例如 Double Buffer 页指出，两个 stage 只是提供存储条件，还需要计算与搬运的正确安排。

这两页也各用一句话收束：评测页落到 GPU 的使用方式，机器人页落到推理耗时对任务效率、以及限时任务成功率的可能影响。具体实验限制和出处保留在演讲者备注中。

## 本报告的排版约定

- 参考样例的深色标题栏和白色正文区。标题、正文、图示和结果各有固定位置。
- 使用霞鹜文楷 LXGW WenKai，标题 40px，正文 26–27px，图中文字 22–27px。时间和百分比不另设超大字级。
- 页面按“任务背景 → 过程图与结果 → 一句结论”阅读。每个案例一页，初次显示即能看到完整内容。
- 所有图内文字和图的结构写在 `slides.md`。状态对照用 Markdown 表格，反馈闭环用 HTML 节点和 CSS 箭头；改字、增删节点与移动计算状态均在页内完成。
- 通用 `lecture` 布局只安排插槽位置，字体、颜色和绘图样式集中在 `style.css`。新增案例沿用同一个布局。
- 不复制样例的学校标识与组织署名。
