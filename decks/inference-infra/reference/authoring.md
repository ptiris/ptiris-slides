# 内容编辑与页面模板

日常编辑只需要打开 `slides.md`。每页的正文、图示标签、状态、结果、页脚和备注都在该文件里，图的结构也在对应页面旁边。

## 内容与排版的边界

| 文件 | 负责什么 | 什么时候修改 |
| --- | --- | --- |
| `slides.md` | 每页内容与图示结构 | 改字、增加案例、增删节点、调整状态 |
| `layouts/lecture.vue` | 通用页面骨架和插槽 | 改变整套报告的页面分区 |
| `style.css` | 字体、颜色、间距、箭头和通用图示样式 | 统一调整观感，或增加可复用的绘图形式 |

`lecture.vue` 不包含案例文字。状态表和反馈闭环也不依赖专用 Vue 组件。

## 新增一页

在 `slides.md` 末尾添加分隔线，再填写下面的区域。`lead` 是背景，`left` 是主体，`right` 是右侧结果，`takeaway` 是结论，`footer` 是页脚。省略 `right` 时主体会自动占满宽度。

```md
---

# 页标题

::lead::

交代任务和条件。

::left::

## 过程

在这里放正文、表格或图。

::right::

## 结果

写出观测结果。

::takeaway::

写一句能从本页过程和结果得到的判断。

::footer::

<span>推理基础设施</span><span>{{ $page }} / {{ $nav.total }}</span>

<!--
讲述提示和来源链接。
-->
```

页码和总页数会自动更新。最后一个 HTML 注释块是 Slidev 的演讲者备注。

## 修改状态对照图

使用普通 Markdown 表格，第一列表示阶段，后续列表示对象。单元格中的 `state-active` 标记当前计算状态。移动该标记，并同时修改相应的文字，即可改变示意图。

```md
<div class="state-matrix" role="group" aria-label="两个执行阶段的状态示意">

| 阶段 | GPU 0 | GPU 1 |
| :--- | :---: | :---: |
| 先执行 | <span class="state-active">计算</span> | 等待 |
| 再执行 | 等待 | <span class="state-active">计算</span> |

</div>
```

在表格里增删列就能改变对象数量，不需要修改循环代码。保留 HTML 容器与 Markdown 表格之间的空行，以便 Slidev 解析表格。

## 修改流程与反馈闭环

`flow-node` 是节点，`flow-arrow` 是两个节点之间的箭头，`flow-return` 是返回路径及说明。节点标题和说明直接写在 `h3`、`p` 中，能正常换行。`tone-warm` 和 `tone-accent` 为节点设置语义颜色。

```html
<figure class="flow-cycle" style="--flow-count: 2" aria-label="观察和执行的循环">
  <div class="flow-row">
    <div class="flow-node">
      <h3>观察</h3>
      <p>读取当前状态</p>
    </div>
    <span class="flow-arrow" aria-hidden="true"></span>
    <div class="flow-node tone-accent">
      <h3>执行</h3>
      <p>改变环境状态</p>
    </div>
  </div>
  <figcaption class="flow-return"><span>返回新的观察</span></figcaption>
</figure>
```

增删节点时，同时增删相邻箭头，并将 `--flow-count` 设为节点数量；默认是 3。节点会自动均分宽度，返回路径连接首尾节点的中心。单向流程只保留 `flow-row`，省略 `flow-return`。

## 修改逐步动画

第 10–16、19、21、23–26、28、30、32、34–35、37–41、44 页使用 Slidev 点击步骤。页面 frontmatter 的 `clicks: 4` 表示初始状态之外还有四步；`$clicks` 从 0 开始控制 `slides.md` 中的文字、显隐和图形坐标。按右方向键或空格前进，左方向键回退；预览链接 `/10?clicks=2` 可直接打开指定步骤。

每一步的讲述重点写在 `gemm-takeaway` 内，讲述细节和 `[click]` 提示位于备注中。改变状态或几何时同步核对数字和来源。

第 10 页用 SM100 的真实教学 tile 配置 BM=128、BN=256、BK=64，展示 X 向右、W 向下、输出 tile 固定的 K 分块过程。完整矩阵在 GMEM/HBM，当前 X/W tile 共 48 KiB 逻辑输入暂存 SMEM，tcgen05 在 TMEM 中累加 FP32，64 轮后读入寄存器处理并写回。寄存器标出地址、循环状态、输出处理与转型，不再仅写“转 BF16”。此图限定单 CTA、SS 操作数路径，区分较早架构的寄存器累加；流水、同步、实际资源分配和替代写回路径放入备注。网格省略大多数 tile，不能据格子数推实际 grid。后续第 15–16 页继续使用自己注明的 64×64 教学算例。

第 12 页只显示当前形状。计算量为 `2mKN` FLOPs；冷数据理想访存为 `2(mK+KN+mN)` B，基于 BF16、X/W 各读一次且 Y 写一次。所有倍数以 m=1 为基准。实际 HBM 流量不等于此理想值，不能删掉复用假设。

第 13–14 页独立使用 A100 80GB SXM 的 BF16 稠密 Roofline：`x = 450 + 686 × log10(I / 0.5) / log10(20000)`，`y = 360 - 260 × log10(P) / 3`。I 为 FLOP/B，P 为 TFLOP/s，上限为 `min(312, 2.039 × I)`。空心点是假设下的上限位置，不是实测。

第 17 页保留通用 Mega Kernel 介绍。VLA 位于全篇末尾：第 42 页为章节页；第 43 页为静态页，以同步推理为背景，画“观测 → VLA 推理 → 执行动作”的串行闭环，突出推理处于任务关键路径。下方横向排列 PhyAI 的 Thor BF16、π0.5、3-view、H=50、10 步、batch=1 记录及延迟、推理频率，不再放重复调用时间线。论文 Figure 5 的吞吐为 7.43 次/秒，换算延迟约 135 ms/次；这不是同步闭环或电机控制频率，也不是原生 OpenPi 基线。结论为“加速推理，有助于提升任务效率与成功率”；适用条件、计时口径与来源留在 slides.md 备注，不凭模型延迟捏造任务成功率。

第 44 页共两个状态（clicks: 1）：初始为 UMA，点击后为 Persistent MegaKernel。UMA 图只画 CPU / GPU 和共用 DRAM、观察 / 动作缓冲；分配与同步条件放在备注。Persistent 图参考用户 MPK 材料的 SM 时间线：上方 MatMul→AllGather 分别执行，有整算子屏障和空等；下方常驻 worker 在输出分块及相关通信依赖就绪后执行 AllGather，与其他 SM 的 MatMul 重叠。页内明确标为多卡示例。上下保持相同任务条长与颜色，不以示意长度计算加速比。右侧强调跨算子流水、多卡计算通信重叠、动态负载调度。一次启动在图中直接标明；CUDA Graph 与细粒度依赖的区别、通信收益的多卡范围及调度成本写在备注。不得用去噪步骤代替算子粒度，也不保证所有中间量留在片上。所有收益需测量，不在图中预分配毫秒预算。

第 19 页分三步显示 KV 增长、权重放不下、算力不足；只有 KV 显存条按容量预算绘制。第 20–32 页按 DP、TP、PP、CP、EP 排列。DP、PP、CP、EP 各两页：第一页静态说明分工，第二页由问题切到应对；TP 用第 22–26 页单独展开。所有矩形、标签与步骤仍写在 slides.md，不创建专用组件。时间条是定性示意，不能当作实测加速比。

第 22 页明确 down 的输入维切分：H0W0、H1W1 都是 m×4096 部分和，All-Reduce 逐元素相加并让两卡保留同样的 Y。第 23 页对比 TP=2 和 TP=8：权重条表示单卡持有份额，每卡乘加次数降至1/4，而部分和形状不变；不把乘加数变化当作耗时变化。

第 24 页按点击先消除本地输出到通信缓冲区的额外拷贝，再融合归约后的 ResidualAdd 与 RMSNorm；不能删除必要归约或声称所有输出零访存。第 25 页使用4卡、4个向量分片演示Ring的6阶段和MultiShot的2阶段：输入值分别为1/2/3/4，owner GPU先汇总一个分片为10，NVSwitch再多播为每卡完整结果；交换机只负责转发，不代替GPU求和。阶段数不代表耗时倍数。第 26 页通过平移通信块演示tile就绪后的流水重叠，A/B/C是已完成本卡K累加的不同输出块，后续计算仍需等待归约。时间线是执行顺序示意；共用SM/HBM和同步的代价在备注中说明，评价看整层/整token延迟。图文与来源均在slides.md，schedule-shift只提供可复用的平移动画。

第 33 页区分互连域内 Scale-up 与域间 Scale-out。第 34 页共三步：Prefilling/Decoding 回顾、混跑干扰、跨超节点分离。标注 Prefill 通常 Compute Bound、低批量 Decode 通常 Memory Bound（显存带宽）；性质会随负载改变。第 35 页保持同一张 KV 图，依次展示发送出口、路径不均和接收汇聚，三个状态是假设不同瓶颈。

第 37–41 页继续沿 KV 展开。第 37 页模型为 BF16、36 层、8 个 KV 头、128 维；第 38 页以 2 token/块示意分页：左右两请求的逻辑块通过箭头映射到中央物理池，格内用两句短英文的字词标出对应 KV，在逻辑块与物理块中保持一致；A 生成 cup 后只新增一组映射和末块空位，原有映射保持不动；第 39 页建立软件 KV 池；第 40 页区分主机中转与 GPUDirect RDMA；第 41 页区分 CXL 容量分配、CPU 地址访问和 GPU 数据路径。虚线地址框表示逻辑映射，不是物理中转缓冲区。

SVG 标签之间不要插入空行：Markdown 可能把后续带缩进的标签当作代码块。编辑后应检查每个点击状态，确认图元没有丢失；除布局检查外还需查看截图。

### 连线与箭头

每条带 `marker-end` 或 `marker-start` 的路径只保留一个 `M`，分别绘制各个分支。汇合线与框体轮廓可以用多段路径，但不要给整条汇合线附加方向箭头。先画容器背景，再画连线和内部节点，避免白色框体盖住箭头。

箭头统一使用 `markerUnits="userSpaceOnUse"`，尺寸为 12 × 12；`arrowhead` 样式通过 `context-stroke` 继承对应连线的颜色，不随强调线宽放大。最后一段直线至少留 16 个 SVG 单位，箭头尖端通常与目标边缘相隔 6–10 个单位。修改折线路径时，同时核对最终朝向、转角与尖端之间的距离。

文字放在连线旁，避免用白底遮住穿过文字的线。数据包可以位于传输线上，但不要覆盖箭头头部。改动后检查所有点击状态，特别是分支箭头、描边变色及逐步显示的部分。

## 标题页、目录与章节页

第 1 页为封面（`class: cover-page`），第 2 页为总览（`class: outline-page`）。第 8、18、36、42 页使用 `class: chapter-page`，分别进入计算、网络、存储与端侧 VLA。它们都沿用 `lecture.vue` 的插槽，没有专用 Vue 组件。

封面只显示 `Introduction to Inference Infra`。每张章节页也只显示一个陈述式概括，写为页内的 Markdown 一级标题；不添加引导语、副标题、步骤、页脚或页码。封面和章节页使用相同的深色背景与居中标题。

目录使用普通有序列表，每行保留章节名和简短内容概括，不添加“先看实际任务”之类的讲述提示。`style.css` 负责字级、留白与排列；所有文字都在 `slides.md` 中修改。

正文页脚的第一个 `span` 是章节名，页面与总页数仍由 Slidev 自动计算。增删章节时，要同步调整目录、章节页和相关正文的页脚，并更新本文件及 README 中的页码链接。

## 调整整体样式

如果一页只需要一张完整的解释图，可以在该页 frontmatter 设置 `class: diagram-page`，只填写 `left` 和 `footer` 插槽。范围问题页给出了 `system-map` 示例：HTML 节点和文字、SVG 连线都在 `slides.md` 中；`style.css` 只定义通用外观。其坐标对应 1168 × 440 的图示区域，文字可以直接修改。

常用设置集中在 `style.css` 顶部的变量中：

| 变量 | 用途 |
| --- | --- |
| `--deck-font` | 字体 |
| `--deck-title-size`、`--deck-body-size` | 标题和正文字号 |
| `--deck-gutter` | 页面左右留白 |
| `--deck-aside-ratio` | 左右栏比例 |
| `--deck-accent`、`--deck-warm` | 图示状态颜色 |

如果某一页需要调整列宽，可以在该页的 frontmatter 中添加 `style: '--deck-aside-ratio: 2fr 1fr'`。正文变长时先调整措辞、换行或列宽，保持投影时可读的字级。

修改后运行 `npm run build`，并打开预览确认中文、图内标签与箭头没有重叠或截断。
